เทียบแต่ละตัวเลือกกับ findings ของ BOA-010 → ตรวจ rationale, trade-off, migration/permission/deep-link impact
== Checklist
01 Option A Conservative — คง 3 กลุ่มเดิม แก้เฉพาะ label Market Overview + permission filter + แบ่ง visual group ของ Settings — เทียบแล้วไม่เลือก
02 Option B Workflow + Data Domains — จัดกลุ่มใหม่ตาม workflow: งานประจำ (Dashboard/User/Asset/Offer/Content) / ข้อมูลและข้อมูลเชิงลึก (Market Data/Market Demand/Option Master) / บริการและกำกับดูแล (Account Deletion/Settings) — ผู้ใช้เลือกเป็น recommendation หลัก
03 Option C Role-adaptive — IA เดียวกับ B แต่แสดงเฉพาะ module/submenu ที่ role มีสิทธิ์ พร้อม role-scoped Dashboard — เทียบแล้วไม่เลือก
04 กำหนดกฎ destination-owned active state → cross-module drill-in เปิด parent ของหน้าปลายทาง แก้เคส DEL-033 → U-1104 ที่ sidebar ค้างผิดกลุ่ม — PASS
05 กำหนด permission visibility rule → none = hidden, limited = เฉพาะ submenu ที่เข้าถึงได้ ห้ามใช้การซ่อนเมนูแทน route/API enforcement — PASS
06 ระบุ quick wins / product decisions / protected impact → การเปลี่ยนจริงต้องแยก Mission และขอ approval — PASS
