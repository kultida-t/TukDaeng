## §0 วิธีใช้ + สภาพแวดล้อม + กติกาที่ล็อก

- **ทดสอบบนเครื่องจริงเท่านั้น** — ติดตั้งแอป build ทดสอบลงมือถือจริง แตะ/ปัด/พิมพ์/เลื่อนบนหน้าจอจริง — **ไม่ใช้ browser, dev console, ปุ่ม dev/demo, localStorage, ข้อมูลจำลอง** — เตรียมสถานะด้วย action จริงในแอป + ข้อมูลจริงบน server เท่านั้น
- **Actors**: `MEMBER` = บัญชีทดสอบบนเครื่องหลัก · `OWNER` = member บนโพสต์/asset ของตัวเอง · `GUEST` = ผ่าน onboarding แล้ว Skip for now · `NEW` = สมัครใหม่ผ่าน flow จริง — เคสที่ต้อง fixture แต่ไม่มี → `BLOCK` ระบุใน Note
- **Type**: `UI` · `POSITIVE` · `NEGATIVE` · `EDGE` · `STATE`
- **วิธีสลับภาษา/ธีมในแอปจริง**: member = `Settings → ภาษา`/`Language` และ `Settings → โหมดธีม`/`Theme mode` — **guest เข้า settings ไม่ได้** (ทั้งชุด gated — GATE-022): ภาษาของ guest = ที่เลือกบนหน้า `lang` ของ onboarding หรือค่าที่ persist บนเครื่องจาก member ก่อน sign out · ธีมของ guest = ค่าธีมของเครื่อง (default `dark`) · **ห้าม** ใช้ทางลัด dev ใด ๆ
- **กติกาภาษาที่ล็อก** (13_SETTINGS §Language Rule + NFR §6):
  1. สลับภาษา **apply ทันทีทั้ง UI** (display-layer swap) — toast `เปลี่ยนภาษาเรียบร้อย`/`Language updated` · ไม่ต้อง kill/refresh แอป
  2. **ทุกข้อความ UI เปลี่ยนตามภาษา** — เจอ string UI ค้างอีกภาษา = **FAIL** (EN hardcode = defect ในแอปจริง — ทุกเล่ม 01–16 ล็อกเหมือนกัน)
  3. **ยกเว้นเท่านั้น**: user-generated content (username/caption/hashtag/bio/ชื่อ collection/ชื่อ alert ที่ user ตั้ง/ข้อความแชท/เนื้อบทความจาก CMS) + proper nouns (ชื่อแบรนด์/รุ่น/Reference ที่ user กรอก เช่น Rolex/Submariner/126610LN) + ชื่อผลิตภัณฑ์ภายนอก (Messenger/LINE/Facebook/Google/Apple) — build ที่**แปล**สิ่งเหล่านี้ = FAIL เช่นกัน
  4. ภาษาไทยใช้ **พุทธศักราช** ในวันที่แบบเต็ม (+543) · ตัวเลขจำนวน/ราคา/badge ใช้เลขอารบิกเหมือนเดิม
  5. ราคาแสดง `THB` + comma · empty state กลาง = `ไม่พบข้อมูล`/`No data found` · terminology ตาม canonical master
- **กติกาธีมที่ล็อก** (13_SETTINGS §Theme Mode Rule):
  1. สลับธีม **apply ทันทีทั้งแอป** ผ่าน theme attribute — ไม่มี toast ไม่มี save button · default `dark`
  2. ทุกหน้า/sheet/dialog/toast อ่านได้ครบทั้ง 2 ธีม — ตัวอักษรจมพื้น/ปุ่มหาย/contrast ต่ำจนอ่านไม่ได้ = **FAIL**
  3. รูปภาพ/วิดีโอที่ user สร้างไม่เปลี่ยนตามธีม; ภาพประกอบ onboarding มี dark variant ของตัวเอง
  4. สีเชิงความหมาย (danger/error/G·L/status/unread) ต้องแยกแยะได้ทั้ง 2 ธีม และ error ต้องมีข้อความ ไม่พึ่งสีอย่างเดียว (NFR §7)
- **สลับกลาง flow**: ในแอปจริง ทางเข้าสลับอยู่ใน settings — เคส "ค้าง" ที่ทำได้จริงคือ stack ลึก + หน้าที่มี draft อยู่บน stack เดียวกัน — state หน้าเดิมต้องไม่หายเมื่อสลับแล้วย้อนกลับ (จุดเฝ้าระวัง §3)
- **ผลเดียวต่อเคส** = `PASS`/`FAIL`/`BLOCK` · ห้ามคำนิ่ม · เจอ string เพี้ยน 1 จุด = เคส FAIL พร้อมจดจุดนั้นใน Note
- **Priority**: `HIGH` = หน้าจอ core flow (feed/viewer/detail/chat/gate/checkout-adjacent) + mechanics กลางแอป · `MED` = secondary · `LOW` = quirk
- **Result column**: เว้นว่าง — tester กรอก `PASS`/`FAIL`/`BLOCK` + ปัญหาใน `Note`
