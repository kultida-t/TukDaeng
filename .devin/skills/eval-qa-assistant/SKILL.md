# Evaluation QA Assistant (ตัวช่วยตอบคำถามประเมินผลงาน)

Skill สำหรับสร้างคำตอบสำหรับแบบประเมินผลงาน (AI Evaluation / CTO Assessment) โดยอิงจากข้อเท็จจริงใน **บันทึกการทำงาน (Task Log / Kanban / Codebase)** 100% เพื่อให้ได้คะแนนระดับสูงสุด (9-10/10) จาก AI ผู้ประเมิน

---

## กฎเหล็ก 4 ข้อ (Core Constraints)

1. **อ้างอิงตรงตาม Log จริง 100% (Strict Ground Truth):**
   * AI ผู้ประเมินจะให้คะแนนเต็ม 10 เมื่อคำตอบระบุ **สาเหตุจริง, ตัวเลขสถิติ, รหัสเคส, ชื่อสถานะ, และกลไกที่ทำจริง** ตรงกับ Log ที่บันทึกไว้
   * ห้ามตอบแบบทฤษฎีทั่วไป หรือคาดเดาสิ่งที่ไม่มีใน Log

2. **ความยาวห้ามเกิน 500 ตัวอักษรต่อข้อ (Strict Length Limit $\le$ 500 Chars):**
   * แต่ละข้อต้องกระชับ ตรงประเด็น เนื้อหาจบในตัวเอง ห้ามยาวเกิน 500 ตัวอักษร (รวมช่องว่าง)
   * ตัดคำฟุ่มเฟือยและบทนำออก ให้เข้าประเด็นทันที

3. **ภาษาคนทำงาน อ่านเข้าใจง่าย เหมือนคนพิมพ์ตอบเอง (Human Developer Voice):**
   * ใช้ภาษาพูดของนักพัฒนาที่คิดแล้วพิมพ์ตอบแบบเป็นธรรมชาติ เหมือนพิมพ์ตอบในฟอร์มประเมินด้วยตัวเอง
   * **ห้ามมีคำลงท้าย ครับ/ค่ะ และห้ามแทนตัวเองว่า ผม/ดิฉัน/เรา**
   * **ห้ามใส่เครื่องหมายคำพูด ("...") และห้ามใส่ Markdown Bold/Italic (เช่น ** หรือ *) เพื่อเน้นคำแบบไม่เป็นธรรมชาติ**
   * **การจัดรูปแบบข้อความ:** ข้อไหนที่เนื้อหาใน Log และคำถามเป็นข้อๆ ให้ใช้การเรียงลำดับตัวเลข (1. 2. 3.) หรือแบ่งย่อหน้าตามจริง ข้อไหนที่เป็นการอธิบายภาพรวมให้เขียนเป็นย่อหน้าเชื่อมโยงกันอย่างเป็นธรรมชาติ

4. **รวมทุกข้อไว้ใน 1 Copy Block เดียว:**
   * สรุปผลลัพธ์ทั้งหมดอยู่ใน Markdown Copy Block (` ```markdown ... ``` `) เดียว เพื่อให้ผู้ใช้ก๊อปปี้ไปส่งต่อได้ทันที

## โครงสร้างคำตอบแยกตามหมวดหมู่คำถาม (Answer Patterns)

### 1. หมวด Improvement (การปรับปรุงเพื่อลดเวลา/แก้งานเกิน Target)
* **โครงสร้างคำตอบ:**
  1. ระบุจุดที่ปรับปรุงได้ชัดเจนใน 1 ประโยคแรก
  2. สรุปความซับซ้อน/สาเหตุเดิมจาก Log (เช่น Cooldown, Quota, Stale, เหตุผลปฏิเสธหลายแบบ, Scope งานกว้าง)
  3. เสนอทางแก้ทางเทคนิคหรือกระบวนการที่เป็นรูปธรรม (เช่น รวมฟังก์ชันตรวจเงื่อนไขตรงกลาง, แตก Subtask ย่อย, แยก Utility อิสระ)

### 2. หมวด Security / Data Protection (ความปลอดภัยและข้อมูลอ่อนไหว)
* **โครงสร้างคำตอบ:**
  1. ลิสต์มาตรการความปลอดภัย 3-4 ข้อสั้นๆ ตาม Security Contract ใน Log
  2. ระบุมาตรการสำคัญ: การ Masking ข้อมูล, การใช้ One-time Token / Hashing, การห้ามบันทึกข้อมูลลับใน Audit/Delivery Payload, และ Safe Recovery States

### 3. หมวด Quality & Testing (เกณฑ์การเลือก Test Scenarios)
* **โครงสร้างคำตอบ:**
  1. ระบุเกณฑ์ภาพรวม (ครอบคลุม Flow ปกติ, ขอบเขตเวลา, จุดเสี่ยงข้อมูลค้าง/ชนกัน, ความปลอดภัย)
  2. ลิสต์กลุ่ม Test Scenarios ตามตัวเลขและชื่อเคสจริงใน Log (เช่น Success/Supersede, Stale State, Cooldown/Quota Boundary, Aggregate Actors, Delivery Failure, Permission/Responsive)

### 4. หมวด Performance (การปรับปรุงประสิทธิภาพ / Caching / Query)
* **โครงสร้างคำตอบ:**
  1. อ้างอิงจุดที่ต้องคำนวณจาก Log (เช่น การนับจำนวน Active Admin, การตรวจสิทธิ์กู้คืน/จัดการ Role)
  2. เสนอโซลูชัน 3 ด้าน: (1) Caching ยอดนับล่วงหน้า, (2) Precomputed Index/Cache สำหรับตรวจสิทธิ์สำคัญ, (3) Database-level Query & Indexing แทน In-memory filter

### 5. หมวด Problem Solving (การแก้บั๊ก / หาสาเหตุและวิธีป้องกัน)
* **โครงสร้างคำตอบ:**
  1. **สาเหตุที่แท้จริง (Root Cause):** ระบุสาเหตุระดับกลไก/โค้ดตาม Log (เช่น Class ค้าง, ข้อมูลจำลองสถานะก่อนหน้าไม่ถูกรีเซ็ต)
  2. **วิธีแก้ไข:** สรุปวิธีแก้สั้นๆ (เช่น ล้างและสร้างข้อมูลใหม่ทั้งชุด, ลบ class เมื่อเปลี่ยนหน้า)
  3. **วิธีป้องกัน:** ระบุ Automated Test และสถิติการรัน Regression Test ตามตัวเลขจริงใน Log

### 6. หมวด Understanding / Business Logic (ความซับซ้อนของระบบ)
* **โครงสร้างคำตอบ:**
  1. ระบุโมดูลและสาเหตุที่ซับซ้อน (เช่น การดึง API ภายนอก, การเชื่อมโยงความสัมพันธ์หลายชั้น, Cross-module dependencies, State Sync พร้อมกันหลายจุด)
  2. อธิบายจุดที่ต้องคิดและออกแบบเป็นพิเศษ (เช่น การจัดการข้อผิดพลาด, Timeline, Grace Period)

## ขั้นตอนการทำงานเมื่อได้รับคำถาม (Execution Steps)

1. **ดึงข้อมูล (Fetch Context):**
   * อ่านบันทึกการทำงาน (Task Log) และโค้ด/เทสต์ที่เกี่ยวข้องจาก Kanban หรือ Workspace
   * ดึงคีย์เวิร์ดสำคัญ: ตัวเลขเคส, รหัส Task, ฟังก์ชัน, สาเหตุบั๊ก, มาตรการความปลอดภัย
2. **ร่างคำตอบ (Drafting):**
   * จับคู่กับ Answer Pattern ตามหมวดหมู่
   * ใช้ภาษาคนทำงานที่กระชับ ตรงประเด็น
3. **ตรวจสอบความยาว (Character Count Verification):**
   * ตรวจนับจำนวนตัวอักษรของคำตอบแต่ละข้อ ต้อง **$\le$ 500 ตัวอักษร** เสมอ
   * หากเกิน ให้ตัดคำเชื่อม ขมวดประโยคให้กระชับโดยคงข้อเท็จจริงสำคัญไว้ครบ
4. **ส่งมอบ (Deliver):**
   * นำคำตอบทุกข้อใส่ใน **1 Copy Block เดียว** พร้อมส่งให้ผู้ใช้
